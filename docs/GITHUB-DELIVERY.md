# GitHub delivery — C
Component interface: intakeIssue receives operator TaskSpec, issue number, allowlist, remote and D's store/enqueueSpec. Issue text cannot change policy.
deliver accepts trusted approval, allowlist, required head check names, baseBranch, remote, prepare and assertLease. Stable SHA256 key over repository and task ID determines the branch. Remote adapter must implement ref (null only on confirmed absence), commit, push (create-only), findPRs (all states, pagination), createPR and checks. prepare must independently apply patch in clean checkout, reject unsafe paths/modes and verify the tree. No automatic merge. No network inside SQLite transaction.
Current tests use a fake remote and known synthetic artifact, not a live patch. Production REST adapter, actual Git preparation, D persistence orchestration and F approval authentication are not implemented in this increment. Required check policy is head-only and deliberately fails closed for merge-test SHA. Live G4 blocked pending authorized fixture repository, runtime and independent F approval. Recovery after lost remote response is tested in-process, not SIGKILL/SQLite. No claim of live acceptance.
